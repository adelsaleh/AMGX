Order-preserving higher-fill ILU — 2026-10-31
===========================================

Current status: experimental; architecture autotuning deferred
------------------------------------------------------------
On 2026-10-31 supplied-order ILU(k) was kept experimental, automatic
architecture tuning was postponed, and the merge followed the qualification
runs of that date. The explicit
block_ilu_backend=cusparse_legacy selection and all existing numerical settings
remain unchanged. Inclusion in the merged library does not make this a default
or automatically selected preconditioner. No new ILU(k) tuning was performed.

The separately qualified native multicolor ILU(0/1) synchronization corrections
preserve their cofactor inverse, determinant fallback, fill and relaxation
policies; their evidence does not extend the supplied-order ILU(k) contract.
See docs/ilu_synchronization_qualification.md for that distinct qualification.
The historical ILU(k) design, tests and numerical limitations below remain
authoritative for this experimental opt-in path.

Scope and distinction from existing AMGX ILU(1)
------------------------------------------------
AMGX already implements native MULTICOLOR_ILU(1). Its symbolic routine in
csr_multiply_detail.cu compares graph colors, and factorization visits color
groups. This extension does not replace that path. It extends the existing
block_ilu_backend=cusparse_legacy path so ilu_sparsity_level=k>=0 preserves the
supplied block-row order. A PARDISO permutation remains external preprocessing.

The underlying NVIDIA bsrilu02 routine is still zero-fill and non-pivoting:
https://docs.nvidia.com/cuda/pdf/CUSPARSE_Library.pdf (bsrilu02, pp134-136 in
Release13.4 consulted2026-10-31). We explicitly construct the ILU(k) factor
pattern first, insert zero values at new positions, and run zero-fill numerical
factorization on that expanded pattern. This is ordinary level-of-fill ILU(k),
not adjacency-power expansion, ILUT, or a pivoting factorization.

Implementation
--------------
include/solvers/natural_ilu_pattern.h implements host symbolic ILU(k).
Original stored blocks, including explicit zeros, start at level0. Processing
pivot j<i updates level(i,t)=min(level(i,t),level(i,j)+level(j,t)+1), t>j.
A sparse min-heap processes lower columns in supplied order; original and newly
retained entries are emitted in sorted column order. An explicit source-to-LU
mapping preserves all original coefficients. Working storage is O(n+nnz(LU)).

src/solvers/multicolor_ilu_solver.cu integrates the pattern only when
block_ilu_backend=cusparse_legacy. The existing device scatter fills private
m_LU.values after zeroing new slots; cuSPARSE factors/applications remain on GPU.
Input m_explicit_A is never replaced by LU, so all operator matvecs/residuals
still use the original matrix. CPU symbolic setup is intentional and reported.
No new coloring is requested. Existing native multicolor ILU behavior remains.

Supported contract: single GPU, square row-major BSR/CSR, int32 canonical block
columns and stored internal diagonal; existing equal-precision real numerical
backend limits still apply. Missing/unsorted/duplicate columns are diagnosed.
The factor limit includes AMGX's extra sentinel block and signed32 scalar value
count. Construction fails explicitly before overflow; it does not silently
truncate fill. GPU allocation is checked against80% of currently free memory.
That check excludes opaque cuSPARSE workspace and later Krylov allocation.
Structural reuse assumes the caller keeps the same sparsity pattern, as before.

Higher-fill follow-up: levels 5, 10 and 20 (2026-10-31)
----------------------------------------------------
A stronger ILU was requested, referring to SciPy with fill factor 10 and
drop tolerance 1e-8. These settings describe threshold dropping, not ILU(10).
SciPy documents fill_factor as a fill-ratio bound and drop_tol separately:
https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.spilu.html
This AMGX extension has no magnitude-based dropping or pivoting. The follow-up
therefore stays with AMGX-only higher ILU(k) and tests
levels 5/10/20; it must not be
reported as equivalent to spilu(fill_factor=10, drop_tol=1e-8). The benchmark's
original residual target 1e-8 is also unrelated to a factor drop tolerance.

No AMGX source or library rebuild was needed: the final library above already
supports these levels. The candidate file and batch launcher now expose them.
The native allocation bound remains (INT_MAX / b^2) - 1 blocks, including an
extra sentinel block. For b8 this permits 33,554,430 factor blocks, approximately
3.39 times the 9,899,450 input blocks. Setup rejects overflow rather than silently
reducing fill; this limit can be reached before H200 memory is exhausted.

The qualification passed in 2 s: 12/12 GPU reference cases passed.
The new 32-block fill-chain fixture deliberately generates levels up to 30;
unpermuted k5/k10/k20 factors have 69/74/84 blocks from 64 input blocks. Thus
these checks actually exercise the requested high fill, instead of reusing a
small graph whose pattern has saturated. Cases cover b8, both real precisions,
original/permuted order, damping, zero/nonzero guesses, coefficient resetup,
and exact preservation of the original operator. Maximum application errors:
FP64 8.98365e-16; FP32 3.75240e-7.
